# Slice 5: uncommon, hybrid and edge modalities

Classified against arena2/synthesis (algebra.ts, structure.ts, programs.ts, rationale.md).

Vocabulary used below:
- Set target `RepSpec`: `exact | range | amrap | timed(seconds)`. Fields: load (mass, optional), effort, rest, tempo(ecc, pause, con, top as numbers).
- `PerformedField`: `reps | load | effort | completed`. There is no performed duration or distance.
- `EventQuery`: `hitAll | missedAny | reps(last|best|worst) | load | effort | e1rm | prescribed | feedback(pump|jointPain|workload|formQuality) | trained | week`. Every query is per slot. There is no sum over sets and no group-level query.
- Session: one exercise and a telescope of steps; `stepUntil(stop(self), max, target)`, where the target does not see `self`. At most one intensifier (`drop-set | rest-pause | myo-reps | cluster`).
- Day `Group`: `single | superset | circuit | emom(every) | amrapFor(cap)`. These are grouping metadata only. A grep of checker.ts and describe.ts finds no rule or describer for groups, so the comment's "slot inside an emom must have a fixed set count" is not enforced yet.
- Ladders: `nth(list1<exercise>, rung, hold)` with state `rung` (`lib/stab-ladder`). Macro phases: `fixed | bounded(advanceWhen) | open`. Inputs: `e1rm, bodyweight, velocity, soreness, readiness`. Dims include `time, length, speed`. There is no energy dimension and no pace (time/length).
- Slot events: `session | weekEnd | cycleEnd | blockEnd`. Rotation: `weekly | alternate`. The clocks are `week`, `trainWeek` and `slotSession`; there is no day or sub-day clock.

Bucket counts: **NATIVE 10 · ONE-NODE 10 · MODEL CHANGE 6 · OUT OF SCOPE 1** (27 programs).

## Patterns this slice demands

**P1. Whole-unit scoring (group outcome).** This is the largest gap: Fran, Cindy, Murph, Hyrox sims, strongman medleys, and S&S's "on the clock". The algebra scores sets per slot, but these programs score a multi-exercise unit by time to complete, by rounds+reps, or by distance in a time cap. Proposed change: `Group` gains `score: 'time' | 'roundsReps' | 'distance' | 'none'` and a performed group record; handlers get `EventQuery group(id, field)`, which fires on the closing session like slot events. Tabata shows the boundary: a score that reduces to a per-set extremum (`reps worst`) is already native; a score over the unit is not. Also, `Group` has no checker rule or describer today, so D1 ("every former has a describer") does not cover day shapes.

**P2. Multi-metric set records.** A carry is load, distance and time at once, and the event picks which one is scored. Hyrox and ATG Zero add distance targets; Hyrox adds pace (time/length) and calories (energy dimension). The needs are `RepSpec distance{m}`, `PerformedField duration | distance`, a pace entry in the Div table, and an `energy` base dimension. Strictly, distance alone would be ONE-NODE; combined with a choice of score it is a model change to the set record.

**P3. Reads over a step's own sets.** Three related one-node gaps share one fix on `StepHandle`:
- `index`: RoP ladders, the Armstrong pyramid, death-by.
- `total`: EDT on the event side (`reps pick:'sum'`), the 100/day quota on the live side.
- `self` visible to a `stepUntil` TARGET: the daily-max auto-ramp.

All three keep the telescope rule, because each reads only earlier sets of the same step.

**P4. Intra-day frequency.** GTG spreads sets across waking hours. The cheapest fix is a `spread` day group (one issued session, sets hours apart, logger keeps it open). The alternative, a sub-day calendar clock with many issued sessions per day, is a model change and is not needed for any program here.

**P5. Duration as a progressed quantity.** RR holds, max hangs and front-lever-style ladders do double progression on SECONDS. `timed` is exact and nothing logs a performed duration, so hold judgment collapses to `completed`. Repeaters add on/off micro-intervals inside a set (`repeats{on,off,n}`).

**P6. Non-numeric skill states.** Already NATIVE via `list1` ladders and a rung counter (`lib/stab-ladder`): RR, ATG elevation, hangboard edges. What this slice adds:
- A ladder whose rungs switch metric (holds to reps). This works through `nth` over set shapes.
- Two sequential axes (assistance down, then load up). This works with a bounded phase and a handoff.
- Implement attributes that are really lengths (edge mm, box height, band colour), currently flattened into distinct exercise refs. That loses the ordering and makes "next smaller edge" a list position rather than a quantity. This is a future model question (parameterized exercises), not a blocker.

**P7. Load frame.** Weighted calisthenics, hangboards, assisted pull-ups and the Murph vest all prescribe ADDED load over bodyweight, sometimes negative. The algebra handles it as arithmetic over `input('bodyweight')`, so the prescription is fine. The logger and renderer need a frame (system / added / assisted) so that e1RM is computed over system load and the ghost shows what the user actually loads. This matches the app's existing logging-type weight semantics.

**P8. Randomness at issuance.** The RoP die and the deck of cards. A seeded `draw(list, seed = issueKey)` stays total and deterministic, and is stamped like any issued fact, so it does not violate the issued-facts law. The die is ONE-NODE (an input or a draw over minutes). The deck is a model change only because the draw reorders exercises inside a group.

**P9. Complexes as atomic exercises.** Iron Cardio, and arguably a Cindy "round", fit natively when one custom exercise ref stands for the whole complex. This is a useful escape hatch, and it is the reason Iron Cardio is NATIVE while Cindy is not: Cindy's score needs partial rounds by exercise.

**P10. Per-side counting.** S&S alternates hands, get-ups are per side, Limber 11 counts passes per side, and split squats are unilateral. Nothing marks a set as unilateral, so volume and prose ("10 per side") are wrong or doubled by convention.

**P11. Content without a generator.** CompTrain-style daily programming has no rule to encode. It belongs in coach-authored issued sessions, not in the method algebra. If the product wants it, the need is a dated-literal-session feed (and a day clock), not new formers.
